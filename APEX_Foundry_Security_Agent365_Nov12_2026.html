10 / Two jobs, one integration to verify

Foundry vs Agent 365: two jobs, one integration

Foundry / workload

Agent definition, model invocation, project access and workload traces. Verify the pinned version and actual SDK response.

Agent 365 / enterprise

Supported registry discovery, ownership and lifecycle oversight. Verify the product record and observed activity independently.

Publication, registration and ingestion require supported integration and licensing. A successful Foundry call proves none of them.

11 / Registration is evidence, not inference

15 / Prove behavior, correlation and integrity

Prove: release gates, traces and a verifiable audit trail

uv run fsa eval --gate · uv run fsa redteam reconcile --strict · uv run fsa trace show S4 · uv run fsa audit verify

Expected acceptance: safe gate passes; isolated unsafe regression fails; strict synthetic reconciliation exits 1; audit tamper names the first broken line. Inspect actual output before asserting any outcome.

Trace IDs correlate records. They do not prove export, delivery, or ingestion into another product.

16 / Defender · documentation only

Defender sees two levels: the deployment and the agent

Deployment / posture

Resource exposure, configuration and supported cloud posture findings. Establish resource scope and applicable plan.

Agent / runtime investigation

Supported activity, threats, entities and incident correlation. Establish the exact workload, signal and observation time.

No simulated alerts. A local blocked request is application evidence only. Consult Defender integration guidance.

17 / Same agent. Different evidence.

Why a finding shows in Defender but not in Agent 365

Enabled ≠ ingested

Check scope → workload eligibility → integration → licence → cloud → observed event.

Resource posture, registry inventory and runtime activity are not equivalent signals. Missing cross-product correlation remains unknown.

18 / Safe adversarial evidence · SYNTHETIC

A red-team verdict is one layer of seven

Evaluator verdict → response → tool invocation → authorization → actual execution → downstream evidence → candidate adjudication.

Raw evaluator fields are preserved. UNKNOWN never counts as pass. Candidate adjudication is not human sign-off or a native Defender detection.

21 / Deployment context

Check every capability in every cloud

22 / CI/CD · fail closed on missing evidence

Release gates in CI, then run it in your own Azure

uv sync --frozen --all-extras --dev · make validate · uv run fsa eval --gate · uv run fsa evidence

Prepare dependencies before the offline session. Isolated unsafe-must-fail CI tests are not a runtime bypass. Separate authorization is required for cloud execution. No deploy, publish, consent or identity change is authorized by this page.

23 / Take the operating model with you

Three takeaways

  1. Protect deliberately. Policy and exact, expiring, independent approval bound authority; all writing stays DRY_RUN.
  2. Prove precisely. Reconcile actual execution, release gates, traces and verifiable audit evidence.
  3. Operate honestly. Assign owners and verify every native product integration independently; unknown stays unknown.
