# Publishing and registry

Foundry `agent deploy --authorize` creates a workload prompt-agent version; it is
not Agent 365 publication. Publishing/connecting an agent is a distinct, authorized
operator workflow using the current Microsoft-supported connection route.

This accelerator does not publish, alter consent, register an identity or invent
a stable Agent Registry REST SDK. Before a live demo, retain the actual registry
entry, agent identifier, owner/sponsor, connection status and observation time
through approved evidence storage. A portal screenshot is operator evidence,
not independent API verification.

The application verifies evidence scope/freshness, not portal authenticity:
[extension lab](../participant-lab/agent365-extension.md). Registry presence
does not prove activity ingestion, correct permission boundaries or Defender/Purview
coverage. If registry is unavailable, label that capability VERIFICATION_REQUIRED
and continue the separate local lab without claiming integration success.
