Build the agent.

A tenant-independent, Python-first accelerator for Microsoft Foundry + Security + Agent 365. Start with deterministic local behavior; verify cloud and enterprise integrations separately.

The scenario is a synthetic equipment-policy assistant. It retrieves permitted policy context, produces a local or Azure model explanation, enforces deterministic policy, and demonstrates human approval before an idempotent dry-run proposal. Model output does not dispatch actions.

Honesty is a control.

L400 / What to inspect after the run

Inspect the command's actual output location, audit JSONL, span JSONL, and proposal receipt. The normal workflow may wait for approval. Approval demonstration is local-only; it must not be used to imply Azure approval authority.

L500 / Why a successful explanation is not a successful control

A plausible model answer cannot establish retrieval authorization, tool policy, or integration coverage. Verify the policy decision and actual tool side effects independently. The intended external side effect is always none.

L600 / Reproducibility boundary

Record the repository revision, dependency lock, policy version, scenario, execution mode, and actual evidence hashes. Local deterministic results and probabilistic Azure model wording have different reproducibility properties.

Public participant documentation / 04

Authenticate each hop.
Authorize each action.#

  1. Caller → application. The local scenario is a demonstrator, not an authenticated user-facing service. Production needs authenticated callers, entitlements, and request integrity.
  2. Application → Foundry. Use the intended Entra principal and least-privilege resource role. A developer credential is not proof of per-user delegation.
  3. Application → retrieval. Apply source permission and classification rules before model context assembly. Treat every retrieved instruction as untrusted data.
  4. Application → writer. Validate the application-authored proposal and policy. Approval is a local human-approval demonstrator, not production authentication. Every writer path remains DRY_RUN.

Model read-only response: neither an instruction in retrieved content nor a tool name in model text can authorize execution. Production approval requires authenticated approvers, expiry, scope binding, replay defense, and separation of duties.

Evidence-status vocabulary

LOCAL EVIDENCE means inspectable application artifacts. VERIFICATION_REQUIRED means a claim needs environmental or product evidence. A reported verified status is only as trustworthy as its provenance and reviewer; local self-attestation cannot authenticate a portal.

L500 / Correlate without leaking content

Use correlation IDs, span context, timestamps, case identifiers, policy version, and hashes. Do not copy secrets, unrestricted prompts, private tenant IDs, or protected data into public evidence bundles. A trace ID is correlation—not proof that a destination ingested a trace.

L600 / Hash-linked does not mean immutable

A chain can expose missing, reordered, or modified records when checked against a trusted expected chain. An attacker able to replace the entire chain can recompute it. Production assurance requires a trusted external anchor, access controls, retention, and review.

Technical reference / 14

Keep model text out
of the dispatcher#

This is illustrative Python, not a copy-paste SDK implementation. The repository's implementation is the source of truth. Syntax highlighting is local CSS; no external highlighter is loaded.

PYTHON / ILLUSTRATIVE SECURITY PATTERN
def explain_then_authorize(request, model, policy, approvals, writer):
    # The response is an explanation, never an executable command.
    explanation = model(request.safe_context)
    proposal = request.application_authored_proposal
    decision = policy(proposal)
    if not decision.allowed:
        return {"status": "DENIED"}
    if not approvals.valid_for(proposal):
        return {"status": "AWAITING_APPROVAL"}
    receipt = writer.dry_run(proposal)
    assert receipt.mode == "DRY_RUN"
    return {"explanation": explanation, "receipt": receipt}

Do not use model output as a tool name, shell command, authorization decision, or approval token. Real production approval must bind authenticated authority to the specific proposal, context, expiry, and replay constraints.
