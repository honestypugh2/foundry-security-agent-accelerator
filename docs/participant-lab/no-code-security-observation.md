# No-code security observation

No Azure tenant, paid model or mutation is needed for this path.
Duration 15 minutes, L200-L300; any current browser. No installation, shell
commands, licensing or resource cleanup. Use only generic examples; do not enter
customer data or share native-console screenshots. If a link is unavailable,
use the offline content rather than assuming a product capability.

1. Open the self-contained [technical portal](../index.html) locally.
2. Select the local execution tab; identify SYNTHETIC and DRY_RUN labels.
3. Use the policy/approval/write explorer to locate independent approval.
4. Compare a safe final answer with a case containing unsafe execution.
5. In verdict/trace explorers, remove required evidence and observe the
   insufficient-evidence explanation.
6. In the cloud and Agent 365 explorers, distinguish settings from actual
   registry/activity/Defender/Purview observations.

Expected learning outcome: explain why a polished answer, quality score, enabled
flag or registry entry cannot establish end-to-end security. HTML exploration is
an educational illustration, not service execution or security validation.
For actual deterministic code execution, use [local lab](local-fallback.md).
The six pillars are an accelerator teaching framework, not certification.
Use [troubleshooting](troubleshooting.md) and [cleanup](cleanup.md) for the code
paths; the no-code path has no generated service evidence to clean up.
